本次更新说明（v1.1 / 文档解析、消息修改、会话管理与无黑框启动）

✨ 核心功能与交互细节

本地文档上传与解析（/upload）： 

支持上传 .txt、.docx、.pdf 以及常见文本与代码格式，全程在本地完成内容提取，无需额外等待网络上传延迟。 

Word 文档兼容段落与表格内容提取，PDF 支持按页抽取文本，纯文本类文件提供多编码自动兜底解码，避免中文乱码。

内置 30,000 字符提取上限控制，在保证关键上下文可用的同时兼顾解析速度与响应稳定性。

消息修改与重生成/分支体验： 

支持对已发送的历史消息进行编辑修改，改完后可重新触发请求生成对应回复，无需从头重打一整段提示词。

修改消息时妥善处理上下文衔接与后续回复状态，避免旧回复残留或分支混乱，方便在调试提示词、调整提问角度时快速对比不同回答。

新对话创建与会话管理细节： 

发起“新对话”时自动重置当前会话上下文与未发送的临时输入/文档挂载状态，确保新话题不受上一轮对话历史或旧文档内容干扰。

历史对话支持持久化保存与切换查看，在切换会话或新建对话时正确同步当前会话列表与消息渲染区，防止串会话或丢失历史记录。

新对话标题与列表状态随交互实时更新，兼顾日常多任务切换时的清晰度与操作连贯性。

一键清理旧进程 + 隐式启动： 

启动脚本在拉起新服务前自动结束残留的 python.exe / pythonw.exe 进程，彻底解决端口占用以及旧进程未退出导致新接口返回 Not Found 的问题。 

采用后台隐式方式启动后端服务并自动拉起前端页面，全程不留命令行黑框，同时将运行输出与报错重定向至日志文件，方便后续排查。

流式对话与搜索开关联动： 

保留 SSE 流式逐字输出，并可根据前端开关控制是否注入联网搜索相关提示。

🛠️ 问题修复

修复了 server.py 中因字符串引号转义不当导致的语法报错（SyntaxError），保证后端能够顺利启动并持续监听 127.0.0.1:8000。 

理顺了前后端联调链路与旧进程清理机制，消除因后台残留旧服务引发的路由未生效和端口冲突现象。

📌 使用与发布提醒

日常启动：直接运行启动脚本即可完成清旧进程、后台挂起后端与打开网页；若遇到异常，可查看同目录生成的日志文件定位原因。

仓库安全：推送或公开分享前，务必确认 server.py 中的 DEEPSEEK_API_KEY 已改为环境变量读取或空占位符，同时避免将日志文件与本地缓存提交到仓库。
